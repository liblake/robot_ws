# 双轮腿机器人 LQR 平衡控制仿真程序讲解

> 目标：说明本仓库里每个文件是做什么的，以及从“启动仿真”到“LQR + VMC 输出力矩”的完整控制流程。
>
> 本仓库实现的是 MuJoCo 双轮腿机器人仿真：左右各一条四连杆并联腿，腿端各装一个驱动轮；控制器采用 LQR 负责轮式平衡、速度跟踪、航向保持，VMC 负责腿高与跳跃轨迹，并通过相位机让两者在腿电机上分时工作。

## 3. 机器人模型与符号约定

### 3.1 机械结构

- 本体：`base_link`，通过 `freejoint` 在 MuJoCo 中可自由运动。
- 左腿：`link1_left → link2_left`，轮子 `wheel_left`；右腿对称。
- 每条腿是四连杆闭链：
  - 主动电机关节：`base_link_旋转-2`（左腿电机）、`base_link_旋转-1`（右腿电机）。
  - 被动关节：`base_link_旋转-4`、`link1_left_旋转-6`，以及右侧对应关节。
  - `link2` 与 `link3` 通过 MuJoCo equality `connect` 形成闭环，`link23_left_connect` / `link23_right_connect`。
- 轮子关节：`link2_left_旋转-13`、`link2_right_旋转-12`。
- 执行器：
  - 轮电机 ctrlrange：`[-1.0, 1.0] N·m`
  - 腿电机 ctrlrange：`[-12.5, 12.5] N·m`
  - 实际控制时，STAND/CROUCH/LAND 等非 EXTEND 相位会二次限幅到 `±3.5 N·m`，EXTEND 允许拉到 `±12.5 N·m`。

### 3.2 方向与角度约定

- 世界前进方向：`+Y`。
- 本体前进方向：`base_link` 的 `+Y`。
- 轮半径：`WHEEL_RADIUS = 0.036 m`。
- 轮轴方向：世界 `+X`。
- 因 URDF 中正轮速使轮子滚向 `-Y`，所以 `WHEEL_FORWARD_SIGNS` 给两个轮子都是 `-1.0`，把“虚拟前进力矩”映射到物理执行器。
- `pitch > 0` 表示向前倾；`pitch_rate = -base_angular_velocity[0]`。
- `roll` 是绕本体 Y 轴的左右倾角，`roll_rate = base_angular_velocity[1]`。

### 3.3 `SimState` 字段

`src/state.py` 的 `extract_sim_state()` 每步输出：

```text
base_position         基座位姿
base_quaternion       基座四元数
base_linear_velocity  基座线速度
base_angular_velocity 基座角速度
pitch, pitch_rate     俯仰角、俯仰角速度
roll, roll_rate       横滚角、横滚角速度
wheel_positions       左右轮角度
wheel_velocities      左右轮角速度
leg_joint_positions   主动腿关节角度
leg_joint_velocities  主动腿关节角速度
contact_count         当前接触数量 data.ncon
```

`model_addresses()` 会把 `model` 中的 root freejoint、各关节 qpos/qvel 地址、各执行器地址缓存起来，避免每一步重复字符串查找。

## 4. 控制架构总览

控制器是“相位独占”结构：

```text
                       ┌──────────────────────────────┐
  cmd_linear_x  ─────► │                              │
  cmd_angular_z ─────► │  CombinedController          │
  cmd_height    ─────► │  根据 JumpPhase 分发          │
  cmd_jump      ─────► │                              │
                       └──────────────┬───────────────┘
                                      │
                 ┌────────────────────┼────────────────────┐
                 │                    │                    │
           STAND                CROUCH/EXTEND/LAND       FLIGHT/FALLEN
                 │                    │                    │
   LQR: forward + roll + yaw   LQR: forward + yaw only   VMC 腿姿态阻尼 / 全 0
   VMC: 腿高 PD                 VMC: 跳跃轨迹独占腿
```

各相位行为：

| 相位 | LQR 轮控制 | LQR 腿 roll 差动 | VMC 腿控制 | 说明 |
|---|---|---|---|---|
| `STAND` | 开：forward + yaw | 通常为 0，roll 找平由 VMC 腿高差实现 | 腿高 PD | 正常站立 / 行进 / 调高度 |
| `CROUCH` | 开：forward + yaw | 不写腿 | 蹲下轨迹 | 腿电机量程全部给 VMC |
| `EXTEND` | 开：forward + yaw | 不写腿 | 蹬伸轨迹 + 大推力 FF | 允许腿力矩拉到 ±12.5 |
| `FLIGHT` | 关 | 关 | 对称腿 pitch_rate 阻尼 | 空中轮力矩无地面反力，不用 LQR |
| `LAND` | 开：forward + yaw | 不写腿 | 落地缓冲轨迹，软 P 硬 D | 吸收冲击 |
| `FALLEN` | 全 0 | 全 0 | 全 0 | 摔倒后不再乱输出 |

这样设计的原因是：LQR 的 roll 差动和 VMC 的高度 PD 都会写到同一条腿电机上，若同时开启会互相抢占量程。相位机在跳跃期间只让 LQR 控制轮子，把腿电机完整交给 VMC 轨迹。

## 5. 启动与控制循环

### 5.1 启动

```bash
uv run python -m src.launch_mujoco
```

`launch_mujoco.py` 的流程：

1. 检查 `mujoco` 依赖，缺失时尝试用 `uv run --with mujoco` 重新拉起自己。
2. 解析命令行参数：`--xml`、`--mode`、`--controller`、`--scenario`、`--flat-ground`、`--terrain-side`、`--enable-gamepad`。
3. 初始化日志目录 `logs/manual/run_时间戳/`。
4. 打印 LUT 的 `theta_range` 和 `h_range`，方便看腿电机是否接近奇异区。
5. 构建模型：

```text
URDF
  └─ _urdf_to_mjcf()
       └─ prepare_mujoco_xml()  网格预处理
            └─ prepare_controlled_mujoco_xml() 添加地形、freejoint、slider、actuator、equality、keyframe
                 └─ MjModel.from_xml_path()
```

6. 重置到 `stand` keyframe，初始化 `cmd_linear_x / cmd_angular_z / cmd_height / cmd_jump`。
7. 创建控制器：默认 `CombinedController(STAND_PARAMS, phase_machine)`；`jump` 场景会立即预规划一次跳跃轨迹并调用 `phase_machine.start_jump()`。
8. 尝试打开手柄，建立 `GamepadCommandMapper`。
9. 进入 `mujoco.viewer` 循环。

### 5.2 每个控制周期

viewer 循环会按墙钟追赶仿真时间，每帧内执行若干次以下操作：

```text
读取手柄 → 写入 cmd_* 滑块
读取 cmd_linear_x / cmd_angular_z / cmd_height / cmd_jump

如果 CombinedController:
  params.target_velocity  = cmd_linear_x
  params.target_yaw_rate  = cmd_angular_z
  params.vmc.nominal_height = cmd_height

检测 cmd_jump 上升沿 → 创建 JumpTrajectory → phase_machine.start_jump()

extract_sim_state(model, data)
control = controller(model, data, state)
clip control 到 actuator_ctrlrange
写物理执行器 ctrl，但保留 cmd_* 滑块 ctrl
mujoco.mj_step(model, data)
恢复 cmd_* 滑块 ctrl
TelemetryLogger 记录该步
```

`step_controlled_model()` 与 viewer 循环协作：物理执行器由控制器写入 `data.ctrl`，而 `cmd_*` 这些“伪执行器”的 ctrl 需要在 `mj_step` 前后保存和恢复，避免被控制器清零。

## 6. `CombinedController` 内部流程

每次调用：

```text
CombinedController.__call__(model, data, state)
  ├─ addresses = model_addresses(model)
  ├─ vmc_control = vmc_controller(model, data, state)
  │     └─ 内部会更新 phase_machine，并计算腿控制量
  ├─ phase = phase_machine.phase
  ├─ FALLEN: 重置积分/锚点，返回 0
  ├─ FLIGHT: 返回 vmc_control（空中腿姿态阻尼）
  ├─ STAND: _handle_stand_entry + _stand_control
  └─ CROUCH/EXTEND/LAND: _handle_jump_entry + _balance_only_control
```

### 6.1 STAND 路径

`_stand_control()`：

1. 若 LQR 未初始化，调用 `_initialize_lqr()`：
   - 计算当前高度/roll bin 下的 5D LQR gain。
   - 计算当前几何平衡 pitch：`equilibrium_pitch_from_geometry()`。
   - 用 `balance_tangent_state_5d()` 生成初始目标，其中 `target[0] = equilibrium_pitch`、`target[1:4] = 0`、`target[4] = target_velocity`。
2. 若 `fixed_height=False`，更新高度/roll bin 的 LQR gain。
3. 计算当前腿高。
4. `_update_lqr_target()` 更新目标：
   - 重新计算 `equilibrium_pitch`。
   - 位置外环：仅 `target_velocity≈0` 且站立时，用位置 PD 把 base 拉回 anchor。
   - 速度目标：

```text
velocity_target =
    target_velocity
  + height_wheel_velocity_ff
  + position_vel_correction
```

   - 速度误差：

```text
velocity_error = velocity_target - current_wheel_vel
pitch_lean = clip(pitch_lean_gain * velocity_error + velocity_ki * integral, ±0.2)
```

   - 目标俯仰：

```text
target[0] = equilibrium_pitch + pitch_lean
target[4] = velocity_target
```

5. 计算 VMC 共模腿力矩造成的 pitch 扰动前馈：

```text
vmc_common_leg = 0.5 * (τ_left_leg + τ_right_leg)
wheel_ff = active_wheel_ff_gain * vmc_common_leg
```

   `active_wheel_ff_gain` 由 `balance_lqr.wheel_ff_gain_for_leg_common()` 根据实测 coupling 计算。它把“腿共同发力导致身体后仰”的干扰提前用轮子抵消，LQR 只处理残差。

6. 调用 `LqrController`：

```text
u = feedforward - K @ (x - target)
```

7. 若两轮均接地，保留 LQR forward 和 yaw；否则清空。
8. 航向保持：
   - 未发转向指令时，`heading_outer_loop` 把航向误差转成 `yaw_rate_ref`。
   - `_compute_yaw_correction` 做 yaw-rate 阻尼/积分。
9. 分配物理执行器：

```text
左轮 = WHEEL_FORWARD_SIGN * (forward_torque - yaw_torque)
右轮 = WHEEL_FORWARD_SIGN * (forward_torque + yaw_torque)
腿  = LEG_ROLL_DIFF_SIGN * roll_torque（STAND 中 roll_torque 通常为 0）
```

10. 把 VMC 腿控制量叠加到腿上，再按相位二次限幅。

### 6.2 CROUCH / EXTEND / LAND 路径

`_balance_only_control()`：

1. 保证 LQR 已初始化。
2. 把 LQR 目标设为“只平衡、不追速度”：

```text
target = [equilibrium_pitch, 0, 0, 0, 0]
```

   原因是跳跃过程中轮速会被瞬时拉大，若继续用 pitch_lean 追 `target_velocity`，会误判成“需要前倾”，反而推倒机器人。
3. 若接触数为 0，`forward_torque` 和 `yaw_correction` 清零，避免空中轮子自由加速、落地反扭。
4. LQR 只写轮子 forward/yaw，不写腿。
5. 腿电机输出完全来自 VMC 跳跃轨迹。

### 6.3 FLIGHT / FALLEN

- `FALLEN`：`_reset_balance_state()`，返回全 0。
- `FLIGHT`：LQR 不输出；返回 `vmc_control`。VMC 在 FLIGHT 中对左右腿电机施加相同的小力矩，用来阻尼 `pitch_rate`，抑制空中翻转。

## 7. LQR 平衡控制器详解

### 7.1 状态

默认使用 5D 切空间状态：

```text
x = [pitch, pitch_rate, roll, roll_rate, wheel_vel]
```

不把 `wheel_pos` 放进 LQR 内环，是为了避免位置反馈在冲击/震荡瞬态与轮子自由运动形成正反馈；位置漂移由外层位置 PD 处理。

对应文件：

- `balance_state.py`：`balance_tangent_state_5d()`
- `balance_lqr.py`：`compute_balance_lqr_gain_5d()`

### 7.2 简化线性模型

`balance_lqr.py` 把机器人近似成两个解耦的倒立摆：

- pitch 平面：由轮子前进力矩控制。
- roll 平面：由左右腿差分/腿高差控制。

控制周期：

```text
dt = 0.002 s
```

5D 离散系统大致为：

```text
x[k+1] = A x[k] + B u[k]
u = [wheel_forward, roll_diff_leg]
```

关键项：

```text
pitch      += pitch_rate * dt
pitch_rate += (g / L) * pitch * dt - (b_vel / L) * wheel_forward
roll       += roll_rate * dt
roll_rate  += (g / L) * roll * dt + (track_width / 2) / (roll_inertia * L) * roll_diff * dt
wheel_vel  += b_vel * wheel_forward
```

其中：

```text
L = 轮轴到质心的等效摆长
b_vel = (1 / WHEEL_RADIUS) / total_mass * dt
```

几何量来自 `_com_height_above_wheels()`、`_track_width()`、`_base_roll_inertia()`。

### 7.3 离散 LQR 求解

`lqr.py`：

```text
P = solve_discrete_are(A, B, Q, R)
K = (R + B^T P B)^{-1} B^T P A
```

`Q = diag(q_diag)`，`R = diag(r_diag)`。

默认权重：

```text
q_diag = [1000, 200, 1000, 200, 300]
r_diag = [200, 400]
```

`Q[0:4]` 主要管 pitch/roll 稳定，`Q[4]` 给轮速反馈一个较弱权重，避免 LQR 内环与外层 pitch_lean 速度 PI 争抢速度控制权。

### 7.4 控制量选择与执行器分配

`balance_lqr.py` 中的选择矩阵说明：

- `_balance_state_selection()`：从完整 MuJoCo 状态挑出 LQR 状态。
- `_lqr_control_selection()`：把 2 维虚拟控制映射到物理执行器。

`combined.py` 的 `_allocate_balance_control()` 进一步叠加 yaw：

```text
左轮 = WHEEL_FORWARD_SIGN[left] * (forward_torque - yaw_torque)
右轮 = WHEEL_FORWARD_SIGN[right] * (forward_torque + yaw_torque)

左腿 roll 差分 = -roll_torque
右腿 roll 差分 = +roll_torque
```

`LEG_ROLL_DIFF_SIGNS` 在 `balance_lqr.py` 中定义：

```text
左腿电机: -1.0
右腿电机: +1.0
```

## 8. VMC 腿高控制器详解

### 8.1 目标：用两个主动腿电机控制每条腿的高度

四连杆是闭链，不能直接对“腿高”做关节空间 PD。解决方法是：

1. 用离线 LUT 把目标腿高转成主动电机角：

```text
target_motor_angle = lut.motor_angle_from_height(target_height)
```

2. 计算四连杆闭链雅可比：

```text
dh/dθ_active
```

3. 在关节空间做 PD：

```text
pid_torque =
    kp_motor * (target_motor_angle - theta_current)
  + kd_motor * (target_motor_rate - theta_rate)
```

4. 加动态前馈：

```text
ff_torque =
    (dh/dθ_active)
  * total_mass
  * (gravity + target_h_ddot)
  / 2
```

当 `target_h_ddot = 0` 时，这就是标准重力补偿；跳跃时把期望垂直加速度转换成推力。

### 8.2 腿高计算

```text
leg_height = base_link.z - wheel.z
```

`VmcController` 在控制前会：

- 计算左右腿高度均值。
- 缓存每条腿相对均值的 neutral offset。
- 支持 roll-leveling：在 STAND 时按左右轮高差/roll 状态生成左右腿高差偏置。
- 支持斜坡 squat：上坡找平需要大高差时降低共模站高，避免伸长腿顶到 LUT 上限。

### 8.3 增益与相位

- STAND 使用 `kp_motor / kd_motor`。
- LAND 使用独立的 `kp_land / kd_land`，P 更软、D 更硬，吸冲击。
- EXTEND 跟轨迹时 `kp_motor/kd_motor` 乘以 1.5；轨迹跑完还留在 EXTEND 时，关闭位置 P，只留速度项和动态前馈。
- FLIGHT 不控制腿高，只对 `pitch_rate` 做对称阻尼。
- FALLEN 输出全 0。

## 9. 相位机与跳跃轨迹

### 9.1 相位机

`phase.py` 中 `JumpPhaseMachine.update()` 的迁移条件：

```text
STAND
  └─ start_jump() → CROUCH

CROUCH
  └─ time_in_phase >= crouch.duration → EXTEND

EXTEND
  ├─ 持续离地 >= takeoff_airborne_confirm 且 vz > 0.3 → FLIGHT
  └─ 超时 2 × extend.duration 仍未离地 → LAND

FLIGHT
  ├─ 重新接地且 vz <= 0 → LAND
  └─ flight_timeout 超时 → LAND

LAND
  └─ land 轨迹结束、有接触、|vz| < 0.2 → STAND

任意相位
  └─ |pitch| > pitch_fallen_threshold → FALLEN
```

### 9.2 跳跃轨迹

`jump_trajectory.py`：

- `CROUCH`：`QuinticTrajectory`，从 `h_start` 平滑降到 `h_low`。
- `EXTEND`：`ConstantAccelerationTrajectory`，从 `h_low` 匀加速蹬伸到 `h_high`，末速度由目标跳跃高度换算：

```text
v_takeoff = sqrt(2 * g * h_air)
```

- `LAND`：着地瞬间根据当前高度、落地速度生成 `QuinticTrajectory`，吸收冲量并回到目标站高。
- `FLIGHT`：不规划轨迹。

## 10. 命令输入与外部环

### 10.1 输入来源

四个 command：

| command | 含义 | 默认范围 |
|---|---|---|
| `cmd_linear_x` | 前进速度目标 | `[-1, 1]` |
| `cmd_angular_z` | yaw 角速度目标 | `[-3, 3]` |
| `cmd_height` | 目标站高 | `[0.07844, 0.142]` |
| `cmd_jump` | 跳跃触发 | `[0, 1]` |

来源可以是 MuJoCo Control 面板滑块，也可以是手柄。

### 10.2 级联外环

```text
cmd_linear_x ──► target_velocity

target_velocity ≈ 0 时：
  position_outer_loop:
    position_error ──► position_kp ──► vel_ref 修正
    base 前向速度 ──► position_kd ──► 阻尼

速度跟踪：
  velocity_error = velocity_target - current_wheel_vel
  pitch_lean = PI(velocity_error)
  LQR target.pitch = equilibrium_pitch + pitch_lean

航向：
  cmd_angular_z ──► target_yaw_rate
  target_yaw_rate ≈ 0 且站立接地：
    heading_outer_loop ──► yaw_rate_ref
  yaw_damping / yaw_ki ──► yaw 修正力矩
```

### 10.3 手柄映射

`gamepad.py` 中 `GamepadCommandMapper`：

```text
cmd_linear_x  ← -left_y * linear_max
cmd_angular_z ← -right_x * angular_max
cmd_height    ← current_height + (rt - lt) * height_rate * dt
cmd_jump      ← 1.0 if button_a else 0.0
```

`launch_mujoco.py` 检测 `cmd_jump` 从低到高的上升沿，只在 `STAND` 相位且未起跳时触发一次跳跃。

## 12. 无头 rollout 与优化

### 12.1 `rollout.py`

`run_rollout()`：

1. 构建受控模型。
2. 重置到 `stand`。
3. 按场景设置初始状态。
4. 每步提取 `SimState`、调用控制器、clip 控制量、写入 `data.ctrl`、`mj_step`，并记录高度、pitch、漂移、控制能量、饱和率等指标。
5. 提前终止条件：非数值状态/控制、摔倒、`|pitch| > 1.5`、drive 场景停滞。
6. 返回 `RolloutResult` 和 `RolloutMetrics`。

### 12.2 `optimize.py`

用 Optuna 采样参数：

```text
VMC: nominal_height, kp_motor, kd_motor, kp_land, kd_land
LQR: q_pitch, q_pitch_rate, q_roll, q_roll_rate, q_wheel_vel
外环: pitch_lean_gain, velocity_ki, yaw_damping, yaw_ki
```

评分函数按场景不同：

- STAND：惩罚 pitch、高度偏差、控制能量。
- DRIVE：奖励前进距离，惩罚 pitch 和控制能量。
- JUMP：奖励跳跃高度，惩罚 pitch。
- STAND_THEN_DRIVE：奖励 10 米直线完成，惩罚横向漂移和 pitch。

支持 warm start、SQLite + 多进程并行。

## 13. 调参顺序

`default_params.py` 顶部明确给出了建议冻结顺序：

1. VMC PD：`kp_motor`、`kd_motor`
2. LAND PD：`kp_land`、`kd_land`
3. FLIGHT 阻尼：`flight_pitch_kd`
4. LQR balance：`q_diag[0:4]`、`r_diag`
5. 前进速度：`pitch_lean_gain`、`velocity_ki`
6. Yaw / heading：`yaw_damping`、`yaw_ki`、`heading_hold_kp`
7. Jump：`air_height_max`、`crouch_depth`、`extend_stroke`

这个顺序反映了一个原则：先让腿能稳定撑住，再让 LQR 把车身立住，最后再叠加前进、转向和跳跃，避免多个环同时调导致互相干扰。

## 14. 一页速记：核心调用链

```text
launch_mujoco.py
  └─ build_controlled_model()
       └─ prepare_controlled_mujoco_xml()

  └─ create_controlled_controller()
       └─ CombinedController(STAND_PARAMS, JumpPhaseMachine(...))

viewer loop
  └─ step_controlled_model()
       ├─ extract_sim_state()
       ├─ CombinedController(model, data, state)
       │    ├─ VmcController(model, data, state)
       │    │    ├─ phase_machine.update()
       │    │    ├─ LUT: height → motor angle
       │    │    ├─ closed-loop Jacobian
       │    │    └─ ff_torque + pid_torque
       │    └─ phase dispatch:
       │         ├─ STAND: LQR + VMC merge
       │         └─ JUMP: LQR wheel only + VMC leg trajectory
       ├─ clip control
       ├─ write data.ctrl
       └─ mujoco.mj_step()
```

其中 LQR 内部：

```text
balance_tangent_state_5d()
  → LqrController
       → u = ff - K @ (x - target)
  → _allocate_balance_control()
       → 轮子 forward ± yaw，腿 roll 差分
```

VMC 内部：

```text
当前腿高
  → 相位机给出 target_height / target_h_dot / target_h_ddot
  → LUT 给出 target_motor_angle
  → 闭链雅可比给出 target_motor_rate
  → PD + 重力/加速度前馈
  → clip
```

## 15. 容易混淆的点

1. **LQR 状态里没有 `wheel_pos`**：默认 5D 状态是 `[pitch, pitch_rate, roll, roll_rate, wheel_vel]`。位置保持由外层位置 PD 负责。

2. **STAND 中 LQR 的 `roll_torque` 通常为 0**：因为 roll 找平由 VMC 的左右腿高差实现，LQR 不再同时写腿，避免冲突。

3. **跳跃期间 LQR 目标不追速度**：`CROUCH/EXTEND/LAND` 会调用 `_set_lqr_target_balance_only()`，目标变为只保持竖直，`wheel_vel=0`。

4. **FLIGHT 不是“全关”**：LQR 确实关掉，但 VMC 仍会对左右腿施加对称 pitch 阻尼，防止空中翻车。

5. **command slider 不是物理执行器**：它们是 `gear=0` 的虚拟执行器，用于接收用户命令；每次控制器写入 `data.ctrl` 后，启动循环会保存并恢复这些滑块值。

6. **腿电机有两级限幅**：执行器硬件 ctrlrange 是 `±12.5 N·m`，但控制代码在 STAND/CROUCH/LAND 再限到 `±3.5 N·m`，只有 EXTEND 允许使用更大的起跳推力。
