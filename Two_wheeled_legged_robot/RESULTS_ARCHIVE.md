## 4. 过程中修掉的“坑”（防止回归）

1. URDF `effort=10` 会变成关节级 `actuatorfrcrange=±10`，腿根本出不了力 → 已在 builder 中删除，由自己的 ctrlrange 管理。
2. 腿高必须用机身原点 `xpos`（不是质心 `xipos`），否则系统性偏高 11mm。
3. 简化 LQR 的轮子模型与实际单步响应差约 3.6 倍 → 2 状态经验 LQR + 实测映射。
4. 轮子方向符号与开源相反（左+1/右-1）；转向在执行器坐标中“左右同号”。
5. 球体碰撞代理会侧滚造成慢速晃动 → 改圆柱。
6. 机身前倾 13° 是质心几何造成的，不是惯量 bug → 轮心后移 75mm 调直。
7. 手柄 Y 轴方向与默认假设相反 → 映射反号；松杆阶跃会摆动 → 指令斜坡限速。
8. 爬坡失稳根因：轮速≠车身速度（爬坡/打滑时轮速虚高），外环误判“超速”
   倒拉轮子 → 速度反馈已改为机身实际前向速度。

## 8. 平地驾驶性能专项（2026-09-11）

目标：把平地加减速 / 刹车 / 转向 / 速度拉到开源对照车
（`wheel_legged_robot_sim-main`，2.2 kg 四连杆并联腿）的水平。

### 8.1 量化差距（无头对照，同一速度曲线，前进方向均为 +Y）

| 指标（0.5 m/s 梯形，1.0 m/s² 加减速） | 开源对照 | 本机（改动前） | 本机（改动后） |
|---|---|---|---|
| 匀速段速度跟踪 rms | 0.038 m/s | 0.126 m/s | **0.015 m/s** |
| 匀速段 \|误差\|max | 0.098 m/s | 0.267 m/s | **0.046 m/s** |
| 0 → 90% 指令加速时间 | 0.88 s | 1.01 s | **0.80 s** |
| 松杆刹车时间（从 0.5 m/s） | 0.75 s | 2.07 s | **0.83 s** |
| 松杆刹车距离 | 266 mm | 489 mm | **279 mm** |
| 转向 cmd 0.5 rad/s 实测 | 0.500 | 0.404 | **0.500** |
| 转向 0 → 90% 上升时间 | — | 3.23 s | **1.20 s** |

### 8.2 根因

1. **速度环比例增益太低**：`pitch_lean_gain` 是"速度误差 → 目标前倾角"的比例项，
   0.15 对应速度环带宽只有 ~1.5 rad/s。加减速完全靠积分慢慢攒，松杆后刹车
   属于"指数衰减"（误差越小倾角越小），尾巴很长。
2. **转向只有 P 阻尼、没有积分**：轮地摩擦需要力矩才能维持转速，纯 P 必然留
   19% 稳态速差（cmd 0.5 → 实际 0.40）。
3. **指令斜坡限速过保守**：线 1.2 m/s²、转向 0.15 rad/s²，后者让"0 → 0.5 rad/s"
   要 3.3 s，手感发钝。
4. **停车积分门控用的是布尔开关**：外部指令刚跨过 0 的那个周期，积分门控从 1
   直接跳到 `smoothstep(|v|/release_speed)`，在目标倾角上留下一次阶跃；
   2 状态轮 LQR 的 K[0]=45 会把它放大成 `45·Δθ` 的轮力矩跳变。
   增益调到 0.35 后这个跳变从 0.05 涨到 0.45 N·m（旧版本被用户感知为"顿挫"）。
5. **转向通道没有输出上限**：`yaw_damping=8` 在机身被外力偏航时可以瞬间输出
   顶到轮子 ±9 N·m 峰值的差动力矩，把本该留给平衡的量程吃光。

## 9. 腿层支撑前馈改为解析式（2026-09-12）

目标：把 VMC 里"撑住整车"的前馈从 `mj_inverse`（qacc=0 接触逆动力学）换成
不依赖仿真器内部量的解析式，对齐开源车思路并为实机做准备。

### 9.1 公式与分解

```text
τ_j = (∂h/∂q_j)·(m_total·g)/N_legs  +  Σ_{i∈腿链} m_i·g·(∂z_i/∂q_j)
       └─ 整车重量经轮子传导的载荷路径 ─┘   └─ 腿连杆自重（标准关节重力矩）─┘
```

第一项就是开源车 `vmc.py` 的 `jacobian[side]·total_mass·gravity/N` 等价形式
（虚功：轮心竖直支承力 F=m·g/N 对应 τ_j=F·∂h/∂q_j）。
第二项开源车可以省（它四连杆空心杆很轻），本机不能省：腿链 3.5 kg/腿 =
总质量的 21%，省掉在膝上差 5.5 N·m、髋上差 3.6 N·m，仿真实测静立腿高
会偏 7.2 mm、pitch 偏 0.0053 rad。

### 9.2 验证（`test_support_ff.py`，新增）

静立姿态下解析式与旧 `mj_inverse` 一致（0.33/0.37/0.42/0.46 m 四个高度，
最大偏差 0.02 N·m / 0.17%）；"撑住整车"判据（把腿电机力矩设成该前馈后腿
关节残余角加速度）解析式 0.00~0.02 rad/s²、零前馈 37~42 rad/s²。

同时发现旧方案的一个隐患：`mj_inverse` 有速度相关项、且会复用上一步的接触力，
在**旋转**这类动态工况下给出错误值——

| 工况 | `mj_inverse` 前馈 | 解析前馈 | 零前馈 |
|---|---|---|---|
| 站立 | 0.00 | 0.00 | 38.39 |
| 直行 0.6 m/s | 0.05 | 0.07 | 38.39 |
| 原地转 0.8 rad/s | **133.60** | **5.86** | 36.69 |

（数值 = 撑住整车残余 \|qacc\| rad/s²，越小越好。原地转时旧方案比"不给前馈"还差。）

### 9.3 改动后效果

平地驾驶逐项不变（0.5 m/s：跟踪 rms 0.015、刹车 279→283 mm、加速 0.80→0.81 s）；
转向 0.6 rad/s 稳态速差不变（0.600/0.599），roll 0.02°→0.34°（仍可忽略）。

**过障明显变好**：同一个 2 cm 单轮梯形坡 + 0.3 m/s，旧方案在 t=10.25 s 翻车
（\|pitch\| 178.6°，三次复现一致），新方案全程不翻（\|pitch\|max 11.4°、
过坡段 roll 峰峰 2.6°→0.8°）。原来记在"斜坡未完成"里的一次翻车其实是
不可靠前馈引起的。

整条过障包线（左轮单侧梯形坡，均不翻车）：

| 坡高 | 0.20 m/s roll 均值/峰峰 | 0.30 m/s | 0.45 m/s |
|---|---|---|---|
| 20 mm | 0.06° / 0.28° | 0.15° / 0.76° | 0.34° / 1.77° |
| 40 mm | 0.29° / 1.69° | 0.75° / 4.19° | 1.20° / 5.73° |
| 65 mm | 0.93° / 6.37° | 1.91° / 9.31° | 2.40° / 10.97° |

对照开源车同一条 65 mm 坡：roll 均值 0.54~0.85°、峰峰 2.4~3.8°。
仍差 2~3 倍，但原因是车本身：半轮距/质心高（抗侧翻余量）本机 0.76、
开源车 1.76——本机 37° 就翻、开源车要 60°，天生对 roll 敏感 2.3 倍。

|---|---|---|
| 0.30 m/s | 通过，pitch 23.3° / roll 13.7° / 离地 40.3% / z 加速度 rms 21.6 | 通过，pitch 11.5° / roll 0.0° / 离地 0.3% / 2.5 |

把它的错误值进一步放大，导致离地 40%+、侧倾 12~20°、两个速度翻车。

> `prepare_controlled_mujoco_xml` 在 `terrain=None` 时不加任何地形，
> 所以它跑的是平地，表里的 roll/air%/sat% 全是 ~0 是假象。
> 上表用"传入 terrain 后再删掉梯形坡 geom"的独立脚本测得。

### 9.4 仍未解决

- 解析式只补重力（含连杆自重），不含速度相关项（Coriolis/离心）。
  实测原地转 0.8 rad/s 时残余 \|qacc\| 5.86 rad/s²，对应腿高误差约 2 mm
  （旧方案 1.25 mm）。腿关节速度本来很低，暂不补；要补时把
  `Σ m_i·g·(∂z_i/∂q_j)` 换成 RNEA 的完整 bias 项即可。

## 10. 地形跟随专项（2026-09-12，接第 9 节）

目标是"把 `roll_level_offset_limit` 那套手搭前馈升级成地形感知的目标倾角参考"。
结论：**真正的杠杆不在倾角参考，而在腿的目标角速度前馈**——把它恢复成 1.0
之后，本机过障/波浪路的指标全面超过开源对照车。

### 10.1 先排除的路（都试过，收益不成立）

| 试的东西 | 现象 | 结论 |
|---|---|---|
| 找平前馈上限 0.02/0.035/0.06/0.10 | roll 峰峰 9.02/9.31/9.31/9.31° | 0.035 已饱和，加限幅无用 |
| 找平 roll 反馈 `roll_level_kp_height` 0.5/1.0/2.0 | roll 峰峰 21.5/21.8/10.9° | 明显变差，维持 0 |
| 找平 roll 阻尼 `roll_level_kd_height` 0.02/0.05 | roll 峰峰 11.6/15.8° | 变差，维持 0.002 |
| 轮子离地时冻结找平估计 | 离地 26→28 步、roll 9.31→8.96° | 无意义 |
| 地形坡度观测器 + 提前刹车倾角 | k=0.5 时 v 冲高 0.303→0.288；k≥0.8 时 pitch 飙到 22~25° | 弱且脆，不采纳 |

还查清了一件容易误判的事：**车身 roll 近似等于 (轮高差 + 腿指令高差)/轮距**
（由虚功/小角度运动学），所以"残余 roll"本质是**腿没跟上指令**，不是姿态参考
没设对。65 mm 坡 @0.3 m/s 时腿的跟随误差只有 4~6 mm，对应 roll 1~1.6°，
与实测 2.7° 同量级——所以该修的是腿的跟随速度。

### 10.2 真正的杠杆：恢复腿的"目标角速度前馈"

上游 VMC 的关节 PD 是
`τ = kp·(θ_target − θ) + kd·(θ̇_target − θ̇)`，其中 `θ̇_target` 由目标腿高的
变化率经雅可比换算而来——它让腿**主动去追**移动中的地形目标。
本机 2026-09-11 把它整个置 0（当时的目标角速率 0.5~0.94 rad/s 会让
`kd·rate` 单独打满 ±30 N·m 软限幅，过障翻车）。

复测发现当时的真因是**支撑前馈用 mj_inverse**（动态下给出错误值，见第 9 节），
不是这条前馈。第 9 节换成解析式之后，恢复它反而变成主要收益来源：

| 场景（过坡段） | `stand_rate_ff_scale`=0 | =0.8 | =1.0（现默认） |
|---|---|---|---|
| 65 mm 坡 @0.3 roll 峰峰 | 9.31° | 0.65° | **0.30°** |
| 65 mm 坡 @0.45 | 10.97°，离地 4.6% | 1.21° | **0.27°，离地 0%** |
| 40 mm 坡 @0.45 | 5.73° | 0.41° | **0.14°** |
| 20 mm 坡 @0.3 | 0.76° | 0.06° | **0.07°** |
| 波浪路 @0.8 离地占比 | 9.4% | 6.5% | **6.6%** |
| 波浪路 @1.0 离地占比 | 20.4% | 18.6% | **18.9%** |
| 平直 0.8 m/s | 逐位不变 | 逐位不变 | 逐位不变 |

腿电机饱和占比没有变差（65 mm @0.45：4.0% → 0.4%；波浪路 @1.0：15.9% → 15.5%）。

新增参数 `VmcParams.stand_rate_ff_scale`（默认 1.0 = 上游行为，0 = 旧行为），
已进 `params_to_dict / params_from_dict`。

## 11. 鲁棒性体检（2026-09-12）

目标：现有结论都来自固定标称场景，不知道离边界多远。脚本：
`test_robustness.py`（4 个场景 × 25 种扰动）。

### 11.1 结论一览

| 维度 | 范围 | 结论 |
|---|---|---|
| 质量 | 全机 ×0.70~×1.30 | 全部 OK |
| 质量 | 只改机身 ×0.70 / ×1.30 | 全部 OK |
| 质心 | 机身前后 ±5 cm | 前移 OK；**后移 5 cm 时行驶 pitch 0.282 > 0.25（WARN）** |
| **控制回路延迟** | **≤5 ms** | **全部 OK** |
| | 10 ms | 4 个场景中 3 个 WARN |
| | **≥20 ms** | **4 个场景全部摔倒** |
| 传感 | IMU 姿态噪声 ≤1.0°、编码器 12bit 量化 | 全部 OK |
| 地面 | 摩擦 ×0.5 / ×2 | 全部 OK |
| 增益 | 平衡增益 ±20%、速度环增益 ±20% | 全部 OK（调参面不尖） |
| 扰动 | 站立时 ±15% 自重水平推力 | **stand WARN：pitch 0.280、y 漂移 0.371 m** |
| 组合 | 质量×1.15 + 20 ms + 传感 | 全部摔倒（延迟主导） |

**唯一硬伤是控制回路延迟**：

| 延迟 | 4 ms | 6 ms | 8 ms | 10 ms | 12 ms | 16 ms | 20 ms |
|---|---|---|---|---|---|---|---|
| stand \|pitch\|max | 0.031 | 0.045 | 0.164 | 0.264 | 0.431 | **摔倒** | **摔倒** |

即：**总延迟 ≤6 ms 完全干净，8~14 ms 退化但还能撑，≥16 ms 直接摔**。
对真机的含义：从 IMU 采样 → 控制解算 → 力矩下发（含电流环）必须压进 ~6 ms。
500 Hz 控制周期本身只有 2 ms，所以这个预算不算苛刻，但必须有意识地去量。

### 11.2 过程中修掉的一个模型地雷

做质量扫描时发现：质量 ×0.85 / ×1.10 / ×1.15 / ×1.20 会让 `mj_forward`
直接返回 NaN（×0.70 / ×0.90 / ×1.30 却正常）。根因是 `mjcf_builder` 造出来的
4 个 `cmd_*` 假滑块关节挂在质量为 0 的 `command_slider_body` 上，又没有给
`armature`，它们的质量矩阵对角只有 MuJoCo 的下限 1e-9 → 整机质量矩阵最小
特征值 ~1e-26，**数值奇异**；改质量后 roundoff 翻符号就崩。

修法：给这 4 个关节加 `armature="1e-4"`（第 11.3 节）。它们只承载手柄/滑块
指令、不带约束也不出力，对机器人动力学零影响——12 个回归脚本数值逐位不变。

### 11.3 体检脚本自身的两个坑（记下来别再踩）

1. **不要在运行时改 `model.body_mass/inertia` 再 `mj_setConst`**：实测对某些
   缩放系数会算出 NaN 模型。改为直接改 XML 的 `<inertial>` 再重新加载。
2. **不要把 IMU 噪声写进 `data` 再 `mj_forward`**：`mj_forward` 会留下按扰动
   状态解出的接触力/热启动项，污染真值，实测让机器人凭空产生 13~15° 稳态倾角。
   正确做法是只改传给控制器的 state 副本。改对之后同一组噪声下
   pitch 标准差只有 0.03°，也就是**控制器对状态噪声几乎免疫**。

### 11.4 体检本身的局限

- 控制器有若干处直接读 MuJoCo 内部量：`data.xmat`(5 处)、`data.xpos/xipos`(8 处)、
  `data.qpos/qvel`(8 处)、以及 **`data.ncon` 接触数**。本体检只对"姿态 + 关节
  编码器"两类做了噪声/量化注入；接触数仍给真值。真机上接触检测本身就是个
  未实现的模块（支撑前馈 `ncon>=2`、站立平衡 `contact_count>=2`、起跳判定
  `ncon==0` 都依赖它）。
- 延迟按"控制器输出滞后 N 步"建模，未含通信抖动、电流环动态、采样抖动。
- 场景只有 4 个（站立/行驶/转向/过障），未覆盖波浪路与高位站姿。

### 11.5 由此得到的结论

1. **需要优先解决的是延迟预算**，不是增益鲁棒性——增益、质量、质心、摩擦、
   传感噪声的余量都很足。
2. **参数标定的可移植性没问题**：±20% 增益偏差、±30% 质量都不影响通过，
   说明换到真机后即使质量/几何有偏差，也不会因为"调参太尖"而失稳。
3. **站立抗持续外力的能力偏弱**（±15% 自重推力 → 漂 0.37 m）。这是设计取向
   （位置环 `position_kp=3` / `position_velocity_limit=0.6` 本身偏软），
   如果实机上需要在坡上/顶风保持站位，需要专门加强。
