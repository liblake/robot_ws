# 双轮足机器人仿真 —— 换电脑复现指南

面向场景：在一台全新电脑上，把这个项目从零跑起来。
所有命令都在 **`Two_wheeled_legged_robot/robot_sim/`** 目录下执行（下文简写为 `robot_sim/`），
除非命令里另有说明。

---

## 1. 先搞清楚要复现哪一个目录

`robot_ws` 仓库里混了好几个来源不同的目录，只有第一个是**你自己的主项目**：

| 目录 | 是什么 | 复现时要不要管 |
|---|---|---|
| `Two_wheeled_legged_robot/robot_sim/` | **主项目**：MuJoCo 仿真 + LQR/VMC 控制 + 论文场景与出图 | ✅ 要 |
| `Two_wheeled_legged_robot/` 下的其他文件 | 文档：迁移指南、结果归档、论文指南、程序讲解、论文 docx/pdf、`paper_draft/` | 参考，不需要安装 |
| `wheel_legged_robot_sim-main/` | 上游同名参考仓库的快照（代码与 `robot_sim` 已不同） | 只需对照参考 |
| `TITA_Description-main/` | TITA 双轮足 ROS2 描述包（URDF/xacro 参考） | 只需对照参考 |
| `wheeled-leg-robot/` | **别人的仓库**（`fernandomierhicks/wheeled-leg-robot`，自带 `.git`），与本项目无关 | ❌ 不要动 |
| `assets/`、`control/`、`text/`、`lqr_balance*.py`、`scence.xml`、`robot_scene.xml` | 早期实验残留 | 可忽略 |

> `robot_sim/` 是一个相对独立的子工程：自带 `pyproject.toml`、`uv.lock`、`README.md`、`.venv/`。
> 只要这个目录在，就够跑仿真了；`robot_ws` 里其他东西都不是依赖。

## 2. 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux（推荐 Ubuntu 22.04+）或 macOS。Windows 未验证 |

本项目当前实测可用的一套版本（供对照）：
Python 3.13.15 / mujoco 3.9.0 / numpy 2.4.6 / scipy 1.17.1 / optuna 4.9.0 / matplotlib 3.11.2。

## 3. 新电脑从零搭建

### 3.1 装 uv

```bash
# Linux / macOS
curl -LsSf https://astral.sh/uv/install.sh | sh
# 或者用 pipx / brew
```

装完确认：

```bash
uv --version
```

> 这一步别跳过。项目用 `uv.lock` 锁了 300+ 个包的精确版本，`uv sync` 才能还原出和原来一致的环境。
> （原电脑上 `uv` 没在 `PATH` 里，但 uv 管理的 Python 3.13 在 `~/.local/share/uv/python/` 下，
> 所以 `.venv/` 是 uv 建的 —— 换电脑时按下面正常装 uv 即可。）

### 3.2 取代码

```bash
git clone <你的仓库地址> robot_ws
cd robot_ws/Two_wheeled_legged_robot/robot_sim
```

> ⚠️ 现在 `paper/` 目录、`analyze_manual_log.py`、`plot_manual_jump.py` 等**还没有提交进 git**，
> 直接 clone 会缺东西。见第 8 节"已知缺口"，先在原电脑上把它们提交上去。

### 3.3 装依赖

```bash
cd robot_sim
uv sync --extra figures          # 要画图就带上 figures
```

`uv` 会自动按 `.python-version` 下载 Python 3.13 并建好 `.venv/`。

> 第一次 `uv sync` 会顺手更新 `uv.lock`（仓库里的 lock 目前没有登记 `figures` 这个 extra，
> 属于过期状态）。更新完记得把新的 `uv.lock` 一起提交，否则别人装出来的还是旧环境。

macOS 上还要接实体手柄的话：

```bash
uv sync --extra figures --extra gamepad
```

若在没有外网镜像的环境，可以临时换源：

```bash
uv sync --extra figures --default-index https://pypi.org/simple
```

### 3.4 验证装好了

```bash
# 1) 依赖版本
uv run python -c "import mujoco, numpy, scipy; print(mujoco.__version__, numpy.__version__, scipy.__version__)"

# 2) 无头自平衡站立 3 秒（最快的冒烟测试）
uv run python test_stand_wheel_balance.py --seconds 3
```

第 2 条正常输出形如：

```
3s CombinedController STAND: |pitch|max = 0.046 |roll|max = 0.0 end_pitch = 0.028 end_z = 0.441 z_min = 0.439 y_max = 0.006 contacts = 4
```

关键看 `z_min` ≈ 0.44（没塌）、`|roll|max = 0.0`（左右没翻）、`contacts = 4`（四轮/腿着地）。
数值不必逐位相同，但**量级要对**：`z_min` 明显小于 0.4 或 `|pitch|max` 超过 0.3 就说明环境或模型有问题。

### 3.5 不用 uv 的备选方案（纯 venv + pip）

`uv` 装不上时，用系统 Python 3.13 手工建环境也能跑：

```bash
cd robot_sim
python3.13 -m venv .venv
.venv/bin/python -m pip install -U pip
.venv/bin/python -m pip install \
    "mujoco>=3.7.0" "numpy>=2.0" "scipy>=1.17.1" \
    "imageio>=2.37.3" "imageio-ffmpeg>=0.6.0" "optuna>=4.8.0" \
    "matplotlib>=3.9"
```

之后把下面所有命令里的 `uv run python` 换成 `.venv/bin/python` 即可
（项目里的 `test_*.py` 和文档默认就写的是 `.venv/bin/python`）。
注意：手工装会拿到最新版而不是锁定的版本，数字可能和论文里差一点点。

## 4. 日常使用

### 4.1 主仿真（带控制器 + 可视化窗口）

```bash
cd robot_sim

# Linux / Windows
uv run python -m src.launch_mujoco

# macOS（MuJoCo 交互查看器必须用 mjpython）
uv run mjpython -m src.launch_mujoco
```

默认就是"加载机器人 + 单轮梯形坡地形 + 控制器"，关窗口结束。**必须在 `robot_sim/` 下运行**，
因为遥测日志按相对路径写到 `logs/manual/`。

### 4.2 常用参数

| 参数 | 作用 |
|---|---|
| `--scenario {stand,jump,drive,fall_recover}` | 动作场景，默认 `stand` |
| `--terrain {ramp,wavy,ramp_wavy,step,none}` | 地形，默认 `ramp` |
| `--flat-ground` | 平地，等价 `--terrain none` |
| `--terrain-side {left,right}` / `--terrain-height` | 单轮梯形坡是哪一侧 / 多高（默认 0.02 m） |
| `--step-height` | `--terrain step` 的台阶高（默认 0.05 m） |
| `--wavy-amplitude` / `--wavy-wavelength` / `--wavy-length` | 波浪路形状 |
| `--rate-ff-scale {0.0,1.0}` | 关节角速度前馈（前馈对照实验用，1.0 为默认开） |
| `--enable-gamepad / --no-enable-gamepad` | 手柄开关，默认开 |
| `--show-collision` | 隐藏外观网格、只显示碰撞体（查碰撞用） |
| `--cache-dir` | 转换后的 MJCF 与预处理网格放哪 |

论文第 4 章那几组场景的命令：

```bash
# 平地运动 / 转向（左摇杆前后、右摇杆左右）
uv run python -m src.launch_mujoco --scenario stand --flat-ground

# 单腿变高度：65 mm 单轮梯形坡（换侧用 --terrain-side right）
uv run python -m src.launch_mujoco --scenario stand --terrain ramp --terrain-side left --terrain-height 0.065

# 波浪路
uv run python -m src.launch_mujoco --scenario stand --terrain wavy

# 跳上台阶（5 / 10 / 15 cm）
uv run python -m src.launch_mujoco --scenario stand --terrain step --step-height 0.05
```

### 4.3 手柄

手柄默认启用，接不上会自动跳过，不影响仿真。映射：

- 左摇杆上下 → 前进/后退，满杆 ±3.0 m/s
- 右摇杆左右 → 转向，满杆 ±0.6 rad/s
- RT / LT → 升降站高（0.31~0.42 m）
- A 键 → 触发跳跃（需在 STAND 相位停稳 ≥1.2 s，否则本次按键被丢弃并打印原因）

Linux 上兼容手柄会被内核暴露成 `/dev/input/js*`，程序自动取第一个，**不需要额外依赖**。
需要确认轴/按键映射时：

```bash
uv run python -m src.gamepad            # 或传具体设备路径
```

### 4.4 只看模型（不加载控制器）

```bash
uv run python launch_viewer.py            # Linux
uv run mjpython launch_viewer.py          # macOS
```

### 4.5 日志在哪

每次 `launch_mujoco` 新建一个运行目录：

```
robot_sim/logs/manual/run_20260925_193208/
  telemetry.csv   # 500 Hz 逐步遥测（位姿/姿态/速度/轮速/接触数/控制量等）
  system.log      # 本次启动参数：地形几何、前馈档位、手柄名等
```

- **只保留最近 4 次运行**（`cleanup_old_logs`），要做对比实验先把目录复制走。
- 手动日志里 `roll` / `pitch` 两列单位是**弧度**，而论文 CSV 里是**度**，别混。

## 5. 实验 / 论文链路（无头批量跑）

### 5.1 场景运行器

```bash
cd robot_sim

uv run python -m paper.run_cases --list                  # 列出全部场景
uv run python -m paper.run_cases --case stand_12s        # 跑单个
uv run python -m paper.run_cases --group terrain         # 跑一组
uv run python -m paper.run_cases --all                   # 跑全部（较慢）
uv run python -m paper.run_cases --case jump_step20 --viewer   # 边看边跑
```

当前共 **33 个**场景，分 5 组：`ff`(3) / `ground`(13) / `height`(6) / `jump`(1) / `terrain`(10)。

不改代码临时覆盖参数（点分路径对应代码字段）：

```bash
uv run python -m paper.run_cases --case ramp_65_03 --set vmc.stand_rate_ff_scale=0 --tag ff_off
```

### 5.2 输出与出图

结果落在 `robot_sim/paper/data/`：`<场景名>.csv`（逐步遥测）+ `<场景名>.json`（汇总指标）+ `index.json`（总索引）。

```bash
uv run python paper/figures/fig5_terrain.py                 # 地形图
uv run python paper/figures/fig_wavy_speed.py               # 波浪路（一次出 7 张）
uv run python paper/figures/fig_single_leg_height_roll_3h.py # 单腿变高度侧倾对照
```

> 出图脚本依赖 `matplotlib`，所以 `uv sync` 时要带 `--extra figures`。

### 5.3 分析手动日志

```bash
# 单次：看看这一趟过坡侧倾多大
uv run python analyze_manual_log.py logs/manual/run_20260921_215312

# 前馈关 vs 开 对比，只看 5 m 梯形坡那一段
uv run python analyze_manual_log.py logs/manual/run_第一次 --label "ff off" \
    logs/manual/run_第二次 --label "ff on" \
    --x y --window-y 0.22:5.22 --pass 1 --out /tmp/ff_compare.png
```

手动日志不可重复，适合自查演示；论文数字请用 5.1 的场景运行器产出。

## 7. 常见问题

**Q: 报 `ERROR: could not initialize GLFW` / `X11: Failed to open display`**
没有可用显示器。可视化窗口需要真实 X11/Wayland + OpenGL。远程服务器请用无头路径
（`test_*.py`、`paper.run_cases`），或用 `Xvfb` + VNC 转发。

**Q: 启动就报 `Nan, Inf or huge value in QACC ... simulation is unstable`**
模型参数被改坏了，或 `--terrain-height` 给得过高（超过 0.065 m 未验证）。先跑平地
`--flat-ground` 排除地形因素。仓库里的 `MUJOCO_LOG.TXT` 是这些历史警告的记录，可以随时删。

**Q: 出图报 matplotlib 找不到 `/home/xxx/.config/matplotlib`**
设置一个可写缓存目录即可：
```bash
export MPLCONFIGDIR=/tmp/mpl
```

**Q: macOS 上 `python -m src.launch_mujoco` 打不开窗口**
MuJoCo 交互查看器在 macOS 必须用 `mjpython` 启动（见 4.1）。

**Q: 手柄读不到**
Linux 先看设备在不在：`ls -l /dev/input/js*`。有的发行版需要把用户加进 `input` 组。
`launch_mujoco` 只取第一个可用设备，多手柄时先拔掉多余的。想排查映射用 `python -m src.gamepad`。

**Q: 换了电脑后论文数字对不上**
先确认 `.venv` 是用 `uv sync` 还原的（版本锁定），再确认没有带 `--set` 覆盖参数。
另外确认 `uv.lock` 是最新的：仓库里那份还没登记 `figures` extra，第一次 `uv sync` 会自动改写它。

**Q: 磁盘占用**
`.venv/` ≈ 430 MB、`paper/data/` ≈ 43 MB、`logs/` 会随运行涨到 ~56 MB（4 次 × 14 MB）。
`logs/`、`paper/.cache/`、`paper/data/*.csv` 都已在 `.gitignore` 里，不会进仓库。
跑长场景时加 `--sample-every 2` 或 `5` 可以把 CSV 体积减半以上。
